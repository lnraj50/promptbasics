Agent performance diagnostic

Why “almost identical” agents diverge

The prompt template is only one part of the actual model request.

Start with the assembled runtime payload. Two agents can share the same model, visible prompt, and tool names while receiving materially different context, tool contracts, state, limits, and execution traces.
Controlled investigation checklist

Recommended experiment: replay 50 representative tasks, capture the full request and tool trace, locate the first divergent step, change exactly one variable, and rerun.

Recommended execution order

Baseline → capture → diff → isolate → rerun → document. First prove both agents are receiving the same pinned model and evaluation inputs. Then find the first divergent trace step. Change only that variable and replay the evaluation set before accepting a conclusion.

Visible parameter experiments

Change one control and observe the difference

Run A, save the result in History, then run B with the same model.

Why you may not see a difference: factual extraction has very few reasonable answers, one run is not statistically meaningful, some models ignore or reject sampling controls, and maximum tokens only changes output when the response reaches the cap. Use the examples below, run each setting 3–5 times, and keep the model and prompt unchanged.

Exact testing procedure
  1. Select only one provider/model so model differences do not hide parameter effects.
  2. Choose an experiment and click Apply A. Run it three times.
  3. Click Apply B. Do not edit the prompt. Run it three times.
  4. Compare vocabulary, structure, completeness, latency, token count, and JSON validity in History.
  5. Repeat with a second model. If the parameter is unsupported, disable sampling controls or choose a model that supports them.

Guide

Production and evaluation notes

Fair comparison

  1. Apply one example.
  2. Select comparable model tiers.
  3. Use identical prompts and limits.
  4. Score correctness before style.
  5. Change one variable, then rerun.

Safe production path

Browser → authenticated proxy → provider API. The proxy allow-lists models, injects secrets, validates payloads, sets quotas/timeouts, and normalizes responses. It must not accept arbitrary upstream URLs.

What to score

  • Accuracy and instruction adherence
  • JSON validity and completeness
  • Latency and token consumption
  • Error/refusal behavior
  • Repeatability across multiple runs
