Definition

Generative AI

Generative AI creates new outputs such as text, code, and media from learned patterns and user instructions.

Definition

Large Language Model (LLM)

An LLM predicts likely next tokens to create responses that feel fluent and useful, but it does not automatically verify truth.

Definition

Prompt

A prompt is the full instruction package sent to the model, including the task, context, examples, constraints, and expected output format.

What LLMs do
  • Summarize and transform text
  • Follow clear instructions
  • Draft content and documentation
  • Extract and restructure information
What LLMs do not do reliably
  • Act as a trusted system of record
  • Guarantee factual accuracy without checks
  • Handle every business situation safely on their own
  • Understand hidden business context unless provided
Prompt and response example
PROMPT: Summarize this service record in 2 sentences: [Customer reported intermittent stalling issue affecting daily commute. Technician diagnosed fuel pump failure through pressure testing. Replaced fuel pump assembly, performed test drive, confirmed issue resolved.]
The model can produce a clean summary from this prompt, but it is generating from what it was given — not independently confirming the record.

Why this matters at ABC/XYZ Company

Business relevance

GenAI can improve efficiency across internal knowledge work, customer support, documentation, analysis, and workflow assistance. It still requires human judgment when quality, accuracy, or policy matters.

  • Token costs rise when prompts are inefficient
  • Hallucinations can create operational and reputational risk
  • Poor prompt design causes inconsistent outcomes
  • Missing context often produces weak recommendations

02 • Prompt Anatomy

Mechanics
Definition

System Prompt

The system prompt sets the role, behavior, tone, rules, boundaries, and output expectations that should stay constant across requests.

Definition

User Prompt

The user prompt provides the specific task, question, input data, and immediate objective for the current interaction.

What gets sent to the model
{ "system": "You are an ABC/XYZ Company inventory analyst...", "messages": [ { "role": "user", "content": "Analyze this aging report..." } ], "max_tokens": 4000 }
Key point: the system field is separate from the conversation messages. Messages usually contain user and assistant turns.
With a system prompt

The model follows a defined role, consistent categories, and expected format more reliably.

Without a system prompt

The model may still respond, but categories, format, and analytical boundaries become less predictable.

Key points
  • Structured prompts with clear instructions produce more reliable results
  • Separating rules from tasks makes prompt behavior easier to manage

03 • Message History

Context and cost
How message history works
Turn 1: [system, user] + response Turn 2: [system, user, assistant, user] + response Turn 3: [system, user, assistant, user, assistant, user] + response
Each new turn carries prior visible conversation forward unless the system is designed differently.
What end users usually see
  • Current message
  • Conversation history
  • Uploaded files
What may also influence responses
  • System prompts
  • Tool instructions
  • Retrieved context
  • Safety controls and policy layers

Why this matters

Operational effect
Token costs multiply

Longer conversations resend more content and increase cost per turn.

Context windows fill up

Long sessions eventually need summarization, truncation, or reset strategies.

Earlier context shapes later responses

Previous instructions and hidden context can influence later answers.

Single-turn requests
  • Lower token cost
  • Independent and easier to parallelize
  • Best for repeated record-by-record processing
Multi-turn conversations
  • Richer context
  • Higher cost
  • Greater risk of long-context confusion
Key takeaways
  • Multi-turn conversations are powerful but more expensive
  • Use single-turn requests when independence and low cost matter
  • Your visible prompt is only part of the model’s full context

04 • Prompt Quality

Practical skill
1. Role framing

Set expertise level and perspective using patterns like “You are...” or “I am...”.

2. Format specification

Tell the model exactly how the output should be organized so it is easier to parse and reuse.

3. Context and constraints

Give relevant business background and boundaries so the response stays on target.

The same task can produce dramatically different results depending on how the prompt is framed.
Good prompt
You are an ABC/XYZ Company inventory analyst. Focus only on vehicles over 60 days in inventory. Return: 1) age category 2) top 3 concerns 3) one specific recommendation Use concise bullet points under 200 words.

analyze this inventory

05 • Capstone

Applied exercise
Capstone

Apply what you've learned

Your capstone challenge is to write both a system prompt and a user prompt that together analyze a large vehicle inventory dataset, identify the 10 least-likely-to-sell vehicles, and return a structured result with reasoning.

System prompt required User prompt required Structured table expected Reasoning required
Weak capstone attempt
System: you are an auto analyst User: give me the summary of top 10 vehicles
This is too vague and does not clearly specify “least-likely-to-sell,” format requirements, or evaluation criteria.
Stronger capstone direction
System: You are an ABC/XYZ Company inventory analyst. Identify slow-moving inventory using days in inventory, condition, price point, and likely marketability. Return a markdown table with VIN, year, make, model, trim, price, days in inventory, and reasoning. User: Analyze the 100-vehicle inventory dataset. Identify the 10 least-likely-to-sell vehicles and provide one action recommendation for each.
This version better defines role, output format, ranking objective, and decision criteria.
Things you did well when prompts are strong
  • Separate rules from the task
  • Clarify the business objective
  • Use concise and structured instructions
Things to consider next time
  • Specify exact output columns
  • Define ranking criteria explicitly
  • State whether reasoning should be short or detailed
  • Tell the model how to treat missing or conflicting data

06 • Summary

Reference guide
Key takeaways
  • System prompts set rules and role; user prompts provide the task and data
  • Messages form an array and long history increases token cost
  • Prompt quality depends on role framing, format specification, and context plus constraints
  • Structured prompts are more predictable and easier to operationalize
  • Hidden context such as system instructions and tools can shape the response
System prompt

Use for: role definition, output requirements, persistent rules, and tone consistency.

User prompt

Use for: specific tasks, live data, questions, and request-specific context.
